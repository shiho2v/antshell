## 챕터 핵심 개념

### 개념 1: 에이전틱 루프
Claude Code가 도구를 호출하고 결과를 받아 다음 행동을 결정하는 반복 실행 구조.
1. **컨텍스트 수집** — 필요한 정보 수집 (CLAUDE.md 포함)
2. **작업 수행** — 실행 계획 수립 후 도구 호출
3. **결과 확인** — 스스로 검증, 문제 발견 시 1단계로 회귀
   - 규칙 기반 피드백 / 시각적 피드백 / LLM 기반 평가

### 개념 2: 컨텍스트 윈도우
한 번의 추론에서 참조할 수 있는 토큰 총량. 적재 순서:
CLAUDE.md → 엔터프라이즈 정책 → 프로젝트 메모리 → 사용자 메모리 → 프로젝트 로컬 메모리

**관리 전략**
| 전략 | 설명 |
|------|------|
| 컴팩션 | 98% 도달 시 자동 요약 |
| `/clear` | 컨텍스트 초기화 |
| 점진적 공개 | 필요 시 skill로 로드 |
| 서브에이전트 | 별도 컨텍스트에서 요약 후 메인으로 반환 |
| 구조화된 메모 | 대규모 마이그레이션·다단계 작업에 적합 |

### 개념 3: settings.json
계층적 구조로 설정 관리. **우선순위 (높음→낮음)**:
관리자 설정 > 엔터프라이즈 정책 > 프로젝트 로컬(`.claude/settings.local.json`) > 프로젝트(`.claude/settings.json`) > 사용자(`~/.claude/settings.json`)

- `deny` 규칙은 다른 모든 규칙보다 우선 적용
- 권한 평가 순서: `deny → ask → allow`
- 팀 공유 지침은 `CLAUDE.md`, 개인용은 `CLAUDE.local.md`

### 개념 4: 체크포인트 & 되감기
파일 편집을 자동 추적하는 실행 취소 안전망 (보관 30일).
- 활성화: ESC 두 번 또는 `/rewind`
- 복구 옵션: 대화만 / 코드만 / 둘 다
- **한계**: Bash 통한 변경·외부 변경은 추적 불가, 버전 관리 대체재 아님
