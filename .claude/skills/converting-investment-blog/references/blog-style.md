# 블로그 문체와 구조 (Blog Style)

원 보고서의 규범을 상속한다: `../../generating-krx-report/references/report-style.md`
**완화되는 것은 형식뿐이고, 근거 규율은 완화되지 않는다.**

## 1. 보고서와 블로그의 차이

| | 보고서 (20장) | 블로그 (8절) |
|---|---|---|
| 독자 | 검증자 | 일반 투자자 |
| evidence ID | 본문에 노출 | **HTML 주석으로 강등** |
| rcept_no | 본문 괄호 안 | 각주 링크 |
| criteria 등급표 | 전량 게재 | **생략** |
| 모듈 구분 | 장 단위로 분리 | 주제로 재배열 |
| 상충 근거 | 문단 안에 병기 | 병기 + **6절에 집약** |
| 면책·출처·기준일 | 필수 | **필수 (완화 없음)** |
| N/A 사유 | 필수 | **필수 (완화 없음)** |

## 2. 8절 구조

| 절 | 제목 | 내용 | 원천 |
|---|---|---|---|
| 1 | 한 줄 요약 | 결론 등급 + 종합점수 + 신뢰도·완전성 | `manifest.composite` |
| 2 | 이 회사는 무엇으로 돈을 버는가 | 사업구조 2~4문단 | `*_business.json` 의 `verdict` |
| 3 | 숫자로 보는 현재 | 핵심 지표 표 (5~8행) | `claim_type == "fact"` |
| 4 | 투자 포인트 3 | 각 3~5문장 | 모듈 `strengths[]` |
| 5 | 리스크 3 | 각 3~5문장 + **CANSLIM 등급표** | 모듈 `weaknesses[]`, risk·trend 모듈 |
| 6 | 이 분석에 대한 반론 | 반론 전량 | devils-advocate + `counter_evidence[]` |
| 7 | 확인하지 못한 것 | 목록 | `unknown` claim + `unsupported_items` |
| 8 | 출처·기준일·면책 | 표 + 면책 원문 | `manifest.sources[]` |

**절을 생략하지 않는다.** 쓸 내용이 없으면 "해당 없음 — (사유)"를 적는다.

## 3. claim_type 별 표현 규칙

| claim_type | 블로그 문체 | 강제 사항 |
|---|---|---|
| `fact` | 평서문으로 그대로 | 수치 + 기준일. DART 수치는 rcept_no 링크 |
| `derived_interpretation` | "…로 보인다", "…로 해석된다" | `counter_evidence_ids` 가 있으면 **같은 문단에 병기** |
| `conditional_view` | "…하면 …할 수 있다" | 단정형 금지. `causal_path` 를 한 문장으로 요약해 붙인다 |
| `unknown` | "확인하지 못했다" | 7절로 이동. **추정으로 대체 금지** |
| (claim 없음) | 연결·전환 문장만 | **수치·판단 포함 금지** |

### claim 주석 다는 법

```markdown
2026년 1분기 매출은 전년 동기 대비 9.9% 감소했다.<!-- CLM-0009 -->
```

- HTML 주석이라 티스토리·GitHub 어디서도 렌더링되지 않는다.
- 한 문장이 여러 claim 에 걸치면 이어 붙인다: `<!-- CLM-0009 --><!-- CLM-0010 -->`
- 표에서는 행의 마지막 칸에 넣는다.
- **수치를 담은 곳에 근거 주석이 없으면 검증기가 FAIL 을 낸다.**
- claim ID 를 본문에 그대로 노출하면 FAIL 이다. 반드시 주석 안에 감춘다.

### 주석의 적용 범위

| 단위 | 범위 |
|---|---|
| 문단 | 빈 줄로 끊길 때까지. 한 문장이 여러 줄로 접혀도 같은 문단이면 주석 하나로 커버된다 |
| **표의 행** | **행마다 따로 달아야 한다.** 윗 행의 주석이 아랫 행을 덮지 않는다 |
| **목록 항목** | **항목마다 따로 달아야 한다.** 이어지는 들여쓴 줄은 같은 항목이다 |

### 채점 항목에는 `<!-- MOD:모듈/항목 -->`

CANSLIM 등급표처럼 **모듈의 채점 내역(`criteria_scores`)에서 그대로 옮긴 값**은 전용 주석을 쓴다.

```markdown
| **M** | 시장 방향 | KOSPI vs 200일선 | +18.1% | 3<!-- MOD:trend/TRD-M --> |
```

- `module-results/{ticker}_{module}.json` 의 `criteria_scores[].criterion_id` 를 지목한다.
  없는 항목을 지목하면 FAIL 이다.
- `MANIFEST` 와 같은 **엄격 규칙**이 적용된다 — 그 줄의 숫자가 채점표·원장 값과 다르면 FAIL.
- `level: null` 인 항목은 **"0점"이 아니라 "미채점"**으로 쓰고 `na_reason` 을 같은 행에 적는다.
  이게 이 분석의 핵심 강점이므로 표에서 감추지 않는다.

`claims.json` 에 없는 수치라도 채점표에 있으면 이 주석으로 인용할 수 있다.
둘 다 없으면 **그 수치는 쓰지 않는다.**

### 차트에는 `<!-- FIG:이름 -->`

```markdown
![연간 매출과 영업이익](https://raw.githubusercontent.com/OWNER/REPO/main/docs/blog/assets/009240/annual_performance.png)<!-- FIG:annual_performance -->

*연간 매출(막대, 좌축)과 영업이익(선, 우축). 출처: DART 연결 사업보고서 연간값.*
```

- 차트는 `scripts/render_charts.py` 가 만든 것만 쓴다. 직접 그리지 않는다.
- 이미지 줄에 `FIG` 주석이 없으면 **FAIL**. 원장(`charts.json`)에 없는 이름이나
  파일이 실제로 없으면 **FAIL**.
- **출처절(8절)·코드블록에 이미지를 넣지 않는다.** 그 구역은 검증에서 제외되므로
  이미지를 숨기는 통로가 된다. 검증기가 전체 이미지 수와 대조해 잡아낸다.
- 모든 차트 아래에 **캡션 한 줄**을 단다: 무엇을(축 포함) · 출처 · 기준.
- 차트 아래 1~3문장으로 **읽는 법**을 쓴다. 그림만 던지지 않는다.

### 차트의 근거 규율

문장보다 그림이 거짓말하기 쉽다. 다음을 지킨다.

- 증감을 보여주는 차트는 **0선을 포함**한다. y축을 잘라 변화를 부풀리지 않는다.
- 두 축을 쓰는 차트는 어느 선이 어느 축인지 캡션에 밝힌다.
- 가격 비교는 **시작일 100 기준 재기준화**로 한다. 절대가격을 겹치지 않는다.
- N/A 는 0 으로 그리지 않는다. 회색 '미채점' 으로 구분한다.
- 데이터가 이상하면(예: 매출이 음수) **그리지 않는다.** 렌더러가 자동으로 건너뛰며,
  그 사실을 본문에 밝힌다. 그럴듯한데 틀린 그림은 틀린 문장보다 위험하다.

### 원장 값에는 `<!-- MANIFEST -->`

종합점수·신뢰도·완전성·가중치처럼 **claim 이 아니라 `manifest` 원장에서 그대로 옮긴 수치**는
전용 주석을 쓴다.

```markdown
종합점수는 55.7점, 판단 신뢰도는 74.3%다.<!-- MANIFEST -->
```

- `MANIFEST` 주석이 붙은 줄의 숫자는 **manifest·evidence 값과 일치해야 하며, 불일치하면 FAIL**이다
  (claim 주석 줄보다 엄격하다 — "원장을 그대로 옮겼다"는 선언이기 때문이다).
- 해석·평가 문장에는 쓰지 않는다. 원장 수치를 인용할 때만 쓴다.

## 3-1. CANSLIM 등급표 (trend 모듈을 실행했다면 필수)

추세 서술을 문장으로만 쓰면 이 스킬의 강점이 드러나지 않는다. 7항목을 표로 낸다.

```markdown
| 항목 | 무엇을 보는가 | 지표 | 값 | 등급 |
|---|---|---|---|---|
| **C** | 최근 분기 실적 | 분기 EPS YoY | -72.7% | 0<!-- MOD:trend/TRD-C --> |
| **A** | 연간 이익 성장 | 3년 영업이익 CAGR | N/A — 기준연도 영업적자로 정의 불가 | 미채점<!-- MOD:trend/TRD-A --> |
```

- 7항목(C·A·N·S·L·I·M)을 **하나도 빼지 않는다.** N/A 항목이 오히려 보여줄 가치가 크다.
- 등급 칸에 `level` 을, N/A 는 `미채점` + `na_reason` 을 쓴다. **0 으로 쓰지 않는다.**
- 표 아래에 "읽는 법" 2~3문장을 붙인다 — 어느 항목이 좋고 나쁜지, 그게 무슨 뜻인지.
- 같은 방식이 valuation(VAL-01~06)·quality(QUA-01~06)·growth(GRO-01~07)에도 그대로 쓰인다.

## 4. 출처 표기 — 강등하되 삭제하지 않는다

| 위치 | 표기 |
|---|---|
| 본문 수치 | 기준일만 남긴다: "2026년 1분기 기준" |
| DART 수치 | 각주 링크: `[공시](https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20260514000456)` |
| 자체 계산값 | "직접 계산한 값" 이라고 밝힌다 (예: "시가총액을 TTM 순이익으로 나눈 값") |
| pykrx 경유 | "비공식 경로로 받은 시세" 라고 밝힌다 |
| 8절 출처 표 | `manifest.sources[]` 를 provider / 종류 / 기준일 로 **전량** 옮긴다 |

**출처·기준일을 붙일 수 없는 숫자는 블로그에 넣지 않는다.** (보고서와 동일)

## 5. N/A 는 N/A 로 쓴다

빈칸도, 0 도, "-" 도 아니다. **사유를 붙인다.**

- 좋음: `EV/EBITDA — 산출하지 못했다. 감가상각비가 재무제표 본문에 공시되지 않았다.`
- 나쁨: `EV/EBITDA: 0` / `EV/EBITDA: -` / (아예 생략)

## 6. 금지 표현 (제목 포함)

**매수 · 매도 · 목표주가 · 적정주가 · 컨센서스 · buy · sell · overweight · underweight**

- 검증기는 **frontmatter 의 `title` 도 검사한다.** 후킹 제목에서 가장 자주 걸린다.
- "순매수 / 순매도" 같은 수급 용어는 허용된다 (투자 권유가 아니다).
- 부정문은 허용된다: "매수·매도 의견을 내지 않는다" (부정어가 **바로 뒤에** 와야 한다).

### 제목 규칙
- (O) `한샘(009240) — 매출은 줄고 이익은 늘었다, 숫자로 본 현재`
- (O) `한샘(009240) 공시로만 본 기업 분석 — 중립적 관찰`
- (X) `지금 사야 할 저평가주 한샘` → 매수 권유
- (X) `한샘 목표주가 5만원?` → 목표주가 금지
- 티커를 제목에 넣는다. 결론 등급을 넣을 거라면 4개 등급 표현 그대로 쓴다.

## 7. 좋은 문장 / 나쁜 문장

**수치**
- (O) "영업이익률은 1.3%다. 2026년 1분기 기준이며 [공시](…)에서 확인할 수 있다."<!-- 예시 -->
- (X) "영업이익률이 1% 초반대로 사실상 남는 게 없는 장사다." → 근거 없는 평가어

**해석**
- (O) "현금흐름과 재무구조는 튼튼하지만 본업 마진은 얇다 — 상반된 두 얼굴로 해석된다."
- (X) "재무구조가 좋으니 결국 주가는 오를 것이다." → 단정적 전망

**전망**
- (O) "주택 거래가 회복되면 고정비가 분산되며 이익률이 개선될 수 있다. 각 단계는 아직 확인되지 않았다."
- (X) "하반기 리모델링 수요 회복으로 실적이 개선될 전망이다." → 단정 + 근거 없음

**반론 (6절)**
- (O) "다만 FCF Yield 8.71%는 매출이 줄면서 운전자본이 풀린 결과일 수 있어, 지속 가능한 현금창출력으로 읽기는 어렵다."
- (X) (반론을 아예 쓰지 않음) → 규칙 위반

## 8. 분량

| 절 | 분량 |
|---|---|
| 1. 한 줄 요약 | 3~5문장 |
| 2. 사업 | 2~4문단 |
| 3. 지표 표 | 5~8행 |
| 4·5. 포인트·리스크 | 각 항목 3~5문장 |
| 6. 반론 | 3~6항목 (모듈 `counter_evidence` 를 빠짐없이 담다 보면 늘어난다) |
| 7. 확인 못한 것 | 목록 7항목 이내 |
| 전체 | 3,000~6,000자 (공백 제외) |

> 분량이 늘어나는 주된 원인은 6절이다. 반론을 줄여서 분량을 맞추지 않는다 —
> 줄일 곳은 2·4·5절의 설명 문장이다.

## 9. 면책 문구 (필수, 원문 그대로)

> 본 글은 공개된 공시·시세 데이터를 기계적으로 집계·채점한 **교육용 기록**이며, **투자 자문이 아닙니다.**
> 특정 종목의 매매를 권유하지 않으며, 목표주가·투자의견을 제시하지 않습니다.
> 데이터는 기준일 시점의 것이며 이후 변경될 수 있습니다. 투자 판단과 그 결과의 책임은 투자자 본인에게 있습니다.

("투자 자문" 또는 "투자자문" 문자열이 없으면 검증기가 FAIL 을 낸다.)
