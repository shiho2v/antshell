# 데이터 정직성 원칙 (환각 방지 3지침)

이 스킬로 보고서를 만들 때 아래 3가지를 **예외 없이** 지킨다.
CANSLIM 채점보다 이 원칙이 우선한다.

## 1) 불확실하면 '확인 필요'로 표시하고 추정하지 않는다
- 수치를 모르거나 계산 근거가 불충분하면 **추정값을 만들지 말고** `확인 필요` 또는 `N/A`로 둔다.
- "대략 ~일 것", "통상 ~ 수준" 같은 추정 표현을 보고서에 쓰지 않는다.
- 전년 동기 데이터가 없어 YoY를 못 구하면 그 항목은 N/A + 사유 1줄.

## 2) 근거는 두 JSON 파일과 rubric 문서로만 한정한다
- 허용 근거: `data/{code}_fundamentals.json`, `data/{code}_market.json`, `references/canslim-rubric.md`.
- **외부 지식(사전 학습 지식, 웹 기억, 유명한 사실)으로 수치를 보완하지 않는다.**
  - 예: "삼성전기는 MLCC 강자다" 같은 정성 서술로 점수를 올리지 않는다.
- JSON에 필드가 없으면 그 항목은 채점하지 않는다(N/A).

## 3) 모든 수치에 (출처, 기준일)을 병기한다
- 재무 수치: `(출처: DART rcept_no=XXXX, 기준일: YYYY-MM-DD)`.
- 시세/수급 수치: `(출처: pykrx, 기준일: YYYY-MM-DD)`.
- 기준일은 각 JSON에 포함된 `rcept_no`/`bsns_year`/`as_of` 값을 그대로 쓴다.
- 출처·기준일을 붙일 수 없는 수치는 보고서에 넣지 않는다.

## 위반 시
- 위 3원칙 중 하나라도 지킬 수 없으면 해당 수치를 보고서에서 빼고 N/A 처리한다.
- 데이터 조회 자체가 실패하면 보고서를 만들지 말고 사용자에게 실패를 알린다.
