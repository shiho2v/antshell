# SPEC-NEWS-001 인수 기준 (Acceptance Criteria)

> Tier M 산출물. `spec.md` §3은 본 문서를 가리키는 포인터다.
> **트레이서빌리티**: REQ-001~REQ-015 전체가 AC-001~AC-015로 **1:1** 커버된다. 모든 AC가 정확히 하나의 REQ를 참조하며, 커버되지 않은 REQ도 고아 AC도 없다. 대응 관계는 문서 끝의 양방향 매핑 표에 있다.
> **검증 수단**: 15개 AC 가운데 자동 테스트로 판정하는 것과 문서화된 수동 절차로 판정하는 것이 나뉜다. 어느 쪽인지는 「검증 수단」 표에 명시했다.

## 인수 기준 목록 (Given-When-Then)

**AC-001**: Given 운영자가 `python scripts/orchestrate_stock_agents.py 008490 --save`를 1회 실행한 뒤, When 저장소의 `data/008490_agents.json`을 읽으면, Then 파일이 존재하고 그 내용이 `spec.md` §4 「유효한 뉴스 문서」 네 조건을 모두 만족하며, `git diff --stat scripts/`의 출력이 비어 있다(수집 스크립트가 변경되지 않았다). (REQ-001)

**AC-002** *(성공 응답 계약)*: Given `monkeypatch.setattr(main, "DATA_DIR", tmp_path)`로 데이터 디렉터리를 임시 경로로 바꾼 상태에서 `005930_agents.json` 픽스처를 놓되 그 `news`가 순서대로 [`"2026-07-06"`(A), `"2026-07-10"`(B), `"2026-07-06"`(C), `"2026-07 (중순)"`(D), `"2026-08 (하순)"`(E)] 다섯 건이고, B만 `"url": "https://example.com/b"`를 가지며, A만 열거되지 않은 키 `"extra": "x"`를 추가로 가질 때, When 클라이언트가 `GET /api/stocks/005930/news`를 호출하면, Then ① 상태 코드가 `200`이고, ② 본문의 최상위 키가 `stock_code`·`news` **정확히 두 개**이며 `stock_code == "005930"`이고, ③ `news`의 길이가 5이고, ④ 순서가 `spec.md` §4 「뉴스 정렬 규칙」이 정한 대로 `[B, A, C, D, E]`이며(규칙 2에 따라 파싱 가능한 3건이 날짜 내림차순, 규칙 3에 따라 같은 날짜인 A·C는 파일 순서 유지, 규칙 1에 따라 파싱 불가한 D·E가 뒤로, 규칙 4에 따라 D·E끼리는 파일에 저장된 상대 순서 그대로 — `"2026-08 (하순)"`인 E가 문자열상 더 나중이어도 D보다 앞으로 오지 않는다), ⑤ 각 항목의 `date` 값이 픽스처의 문자열과 문자 단위로 동일하고(`"2026-07 (중순)"`·`"2026-08 (하순)"`이 그대로 실린다), ⑥ `url` 키가 B에만 존재하며 A·C·D·E에는 `url` 키 자체가 없고, ⑦ 응답의 A 항목에 `extra` 키가 값 `"x"`로 그대로 실린다(`spec.md` §4 「응답 계약」 — 항목의 열거되지 않은 키는 통과시킨다), ⑧ 같은 픽스처의 `news`만 빈 배열 `[]`로 바꿔 같은 요청을 다시 보내면 상태 코드가 `200`이고 최상위 키는 여전히 `stock_code`·`news` 두 개이며 `news`의 길이가 `0`이다(빈 배열은 「유효한 뉴스 문서」 위반이 아니다 — `spec.md` §4). (REQ-002)

**AC-003** *(`news` 밖 내용 비노출)*: Given 임시 데이터 디렉터리의 픽스처가 `ticker`·`name`·`news`·`financials` 네 최상위 키를 모두 가지고, `news` 항목의 어떤 문자열에도 `financials`·`ticker`·`name`이라는 단어가 들어 있지 않을 때, When `GET /api/stocks/005930/news` 응답을 검사하면, Then 본문의 최상위 키가 `stock_code`·`news` 두 개뿐이고, 본문 전체를 JSON 문자열로 직렬화했을 때 `"financials"`·`"ticker"`·`"name"` 세 문자열이 한 번도 나타나지 않는다. (REQ-003)

**AC-004** *(허용 종목이지만 파일 부재)*: Given 임시 데이터 디렉터리에 `008490_agents.json`이 없을 때, When 클라이언트가 `GET /api/stocks/008490/news`를 호출하면, Then 상태 코드가 `404`다. (REQ-004)

**AC-005** *(허용 목록 밖 — 파일 접근 이전 거부)*: Given 임시 데이터 디렉터리에 `005380_agents.json`을 유효한 내용으로 **실제로 만들어 둔** 상태에서 파일 열기 경로에 감시를 걸었을 때, When 클라이언트가 `GET /api/stocks/005380/news`를 호출하면, Then 상태 코드가 `404`이고 응답 본문에 그 파일의 뉴스 내용이 전혀 포함되지 않으며, 파일 열기가 한 번도 호출되지 않았음을 mock으로 검증할 수 있다. 같은 단언이 `code`에 `../005380`·`..%2F..%2Fetc%2Fpasswd` 같은 경로 조작 문자열을 넣은 경우에도 성립한다. (REQ-005)

**AC-006** *(열화된 파일 처리)*: Given 임시 데이터 디렉터리의 `005930_agents.json`이 아래 여섯 가지 상태 각각일 때 — (a) JSON으로 파싱되지 않는 바이트열(조건 1 위반), (b) 최상위 객체에 `news` 키가 없음(조건 2 위반), (c) `news`의 값이 리스트가 아닌 문자열(조건 2 위반), (d) `news`의 원소 하나가 객체가 아닌 문자열(조건 3 위반), (e) `news`의 원소 하나에 `summary` 키가 없음(조건 4 위반), (f) `news`의 원소 하나의 `title` 값이 문자열이 아닌 숫자(조건 4 위반) — When 각각에 대해 `GET /api/stocks/005930/news`를 호출하면, Then 여섯 경우 모두 상태 코드가 `500`이고, 응답 본문 문자열에 임시 데이터 디렉터리의 절대 경로, `_agents.json` 파일명, `Traceback` 문자열, 예외 클래스명(`JSONDecodeError`·`KeyError`·`TypeError`·`AttributeError`)이 하나도 포함되지 않는다. (REQ-006)

**AC-007** *(요청 경로 부작용 금지)*: Given `GET /api/stocks/005930/news`가 정상 응답하는 픽스처 상태에서 `subprocess.run`·`shutil.which`·`httpx`·`urllib.request.urlopen`을 호출 시 테스트가 실패하도록 감시를 걸어 두고 데이터 디렉터리의 파일 목록과 각 파일의 바이트를 미리 기록했을 때, When 요청 처리가 완료되면, Then 네 감시 대상이 한 번도 호출되지 않고, 데이터 디렉터리의 파일 목록과 각 파일의 바이트가 요청 전과 동일하다. (REQ-007)

**AC-008** *(종목 선택 시 뉴스 표시)*: Given 로그인한 사용자가 대시보드를 보고 있고 백엔드가 `005930`에 대해 뉴스 3건 이상을 응답하는 상태일 때, When 사용자가 보유 종목 테이블에서 삼성전자 행을 클릭하면, Then ① 뉴스 영역에 그 응답의 항목이 **응답에 실린 순서 그대로** 나열되고, ② 각 항목에서 `title`·`source`·`date`·`summary` 네 값이 모두 화면에서 읽히며, ③ 표시된 `date` 문자열이 API 응답의 `date` 값과 문자 단위로 같고, ④ `title`이 `"<b>태그</b>"`, `summary`가 `"<img src=x onerror=alert(1)>"`인 임시 픽스처로 바꾸어 다시 렌더링하면 두 문자열이 **문자 그대로**(굵은 글씨나 이미지 요소가 아니라 `<b>태그</b>`·`<img src=x onerror=alert(1)>`라는 글자로) 화면에 보이고 경고창이 뜨지 않는다 — 뉴스 텍스트 필드는 원시 HTML로 해석되지 않는다. (REQ-008)

**AC-009** *(링크 조건부 렌더링)*: Given 뉴스 응답에 ① `"url": "https://example.com/a"`를 가진 항목, ② `"url": "HTTP://example.com/b"`를 가진 항목, ③ `"url": "javascript:alert(1)"`을 가진 항목, ④ `url` 키가 없는 항목이 함께 들어 있을 때, When 뉴스 영역을 렌더링하면, Then ①과 ②의 제목은 앵커 요소이고 그 `target`이 `_blank`, `rel`이 `noopener noreferrer`이며 클릭 시 새 탭에서 해당 주소가 열리고, ③과 ④의 제목은 앵커 요소가 아닌 텍스트로 렌더링되어 클릭해도 아무 이동이 일어나지 않는다. (REQ-009)

**AC-010** *(표시할 뉴스가 없는 네 상태)*: Given 아래 네 상황을 각각 만들었을 때 — (a) 페이지 진입 직후 아직 종목을 선택하지 않음, (b) 아래 「지연 상태를 만드는 방법」의 스로틀링 프로파일(지연 5000ms)을 켠 채 종목을 선택하고 응답이 도착하기 전 구간을 관찰, (c) 백엔드를 멈추거나 `404`/`500`을 반환하게 함, (d) `news`가 빈 배열인 응답을 반환하게 함 — When 대시보드를 렌더링하면, Then 네 경우 모두 뉴스 영역 안에 안내가 표시되고 **네 안내 문구가 서로 다르며**, 네 경우 모두 헤더·포트폴리오 요약·보유 종목 테이블·주가 차트·GitHub 이슈 영역이 정상 렌더링되고 페이지가 예외로 중단되지 않는다. (REQ-010)

**AC-011** *(직전 응답 무효화)*: Given 아래 「지연 상태를 만드는 방법」의 스로틀링 프로파일(지연 5000ms)을 켜 두어 **두 종목 요청이 똑같이 지연되고**, 검증 전에 `GET /api/stocks/005930/news`와 `GET /api/stocks/000660/news`를 각각 한 번씩 호출해 삼성전자 응답의 첫 기사 제목(`T5930`)과 SK하이닉스 응답의 첫 기사 제목(`T0660`)을 적어 둔 상태일 때 — 두 제목은 서로 다른 문자열이며, 이것이 화면에 표시된 뉴스가 어느 종목의 응답인지 가르는 유일한 관찰 근거다 —, When 사용자가 보유 종목 테이블에서 삼성전자를 선택하고 **약 3초 뒤**(삼성전자 응답이 아직 도착하지 않은 시점) SK하이닉스를 선택한 다음, 개발자도구 네트워크 탭에서 두 요청이 **모두 완료 상태로 바뀔 때까지**(약 8초) 뉴스 영역에서 눈을 떼지 않고 관찰하면, Then ① 관찰 구간 전체에서 `T5930`이 뉴스 영역에 **한 번도** 나타나지 않고(그동안 뉴스 영역은 로딩 상태를 유지한다), ② 두 요청이 모두 완료된 뒤 뉴스 영역에는 `T0660`으로 시작하는 SK하이닉스 응답의 항목만 표시되며, ③ 그 뒤 3초를 더 기다려도 표시 내용이 바뀌지 않는다. 판정이 성립하는 이유: 두 요청의 지연이 같아도 **먼저 보낸 삼성전자 요청이 먼저 완료되므로**, 직전 요청을 무효화하지 않는 구현에서는 `T5930`이 약 3초 동안 화면에 노출되어 ①이 깨진다 — 비대칭 지연 없이도 결함이 드러난다. ①이 깨지면 「오래된 응답이 잘못 표시됨」, ①·②·③이 모두 성립하면 「정상」으로 기록한다. (REQ-011)

**AC-012** *(스냅샷 표기)*: Given 뉴스 목록이 정상 표시된 상태일 때, When 뉴스 영역을 관찰하면, Then 표시 내용이 실시간 뉴스가 아니라 사전 수집된 스냅샷임을 알리는 문구가 뉴스 영역 안에 존재하고, 수집 시각·수집 주기·수집 방법을 구체적인 값으로 제시하는 표기는 존재하지 않는다(원본 파일에 그런 필드가 없으므로 만들어 내지 않는다). (REQ-012)

**AC-013** *(하드코딩 뉴스 제거)*: Given 본 SPEC의 프론트엔드 변경이 적용된 상태에서, When `grep -c 'MOCK_NEWS' frontend/src/app/dashboard/page.tsx`를 실행하고 대시보드를 렌더링하면, Then grep 결과가 `0`이고, 화면의 뉴스 영역에 `'삼성전자, 3분기 영업이익 10조 돌파 전망'`·`'SK하이닉스 HBM4 양산 일정 앞당겨'`·`'코스피, 외국인 순매수에 2,650선 회복'` 세 문구가 어떤 종목을 선택하더라도 나타나지 않는다. (REQ-013)

**AC-014** *(API 주소 관례)*: Given `frontend/src/components/StockNews.tsx`가 존재할 때, When 파일을 검사하고 두 환경에서 화면을 띄우면, Then ① 파일에 `process.env.NEXT_PUBLIC_API_URL`과 기본값 `'http://localhost:8000'`을 함께 쓰는 관례가 존재하고(`dashboard/page.tsx:16`·`StockChart.tsx:12`와 동일), ② `NEXT_PUBLIC_API_URL`을 설정하지 않은 상태에서는 브라우저 네트워크 탭의 요청 대상이 `http://localhost:8000/api/stocks/{code}/news`이며, ③ `NEXT_PUBLIC_API_URL`을 다른 주소로 설정하고 다시 띄우면 요청 대상이 그 주소로 바뀐다. (REQ-014)

**AC-015** *(기존 기능 회귀 없음)*: Given 본 SPEC의 변경이 모두 적용된 상태에서, When 기존 라우트(`GET /health`, `GET·PUT·DELETE /api/settings/notion`, `POST /api/report/notion`, `GET /api/github/issues`, `GET /api/stocks/{code}/ohlcv`, `GET /api/stocks/{code}/indicators`)를 호출하고 대시보드를 렌더링하고 `git diff` 및 `git status`를 확인하면, Then ① 기존 백엔드 테스트(`test_chart.py`·`test_indicators.py`·`test_notion_settings.py`)가 전부 통과하고, ② `backend/app/main.py`의 기존 라우트 함수 본문에 대한 diff가 0줄이며, ③ 대시보드의 포트폴리오 요약·보유 종목 테이블·주가 차트·GitHub 이슈·Notion 저장 버튼·헤더가 정상 동작하고, ④ `data/` 아래 기존 파일 가운데 변경된 것이 없다(`git status --porcelain data/`가 `data/008490_agents.json` 한 줄 외에 아무 줄도 내지 않는다). (REQ-015)

## 검증 수단 (Verification Means)

저장소에는 프론트엔드 테스트 프레임워크가 없다 — `frontend/package.json`의 devDependencies에 jest·vitest·`@testing-library`가 없고 `scripts`에 `test`가 없다. 도입은 본 SPEC의 범위 밖이므로(`spec.md` §5), 화면 AC는 **문서화된 수동 절차**로 판정한다. 아래 표가 AC별 판정 수단의 단일 목록이다.

| AC | 판정 수단 | 실행 위치 |
|---|---|---|
| AC-001 | **수동** — 운영자가 스크립트를 1회 실행한 뒤 「유효한 뉴스 문서」 네 조건 확인 + `git diff --stat scripts/` | 결과를 `progress.md`에 기록 |
| AC-002 ~ AC-007 | **자동** — `backend/tests/test_news.py` | CI 기능 단계 ⑤ `pytest backend/tests/ -v`가 그대로 실행한다. CI 설정 변경이 필요 없다 |
| AC-008 ~ AC-012 | **수동** — `docs/weekly/WEEK_10.md`의 「대시보드 뉴스 영역 수동 검증 절차」 + 자동 보조 게이트(`npm run lint`, `npm run build`) | 수동 절차는 M2 산출물, 1회 실행 결과는 `progress.md` 매트릭스에 기록 |

### 수동 검증 절차 문서의 요건 (M2 산출물)

`docs/weekly/WEEK_10.md`의 「대시보드 뉴스 영역 수동 검증 절차」 절은 AC-008~AC-014와 AC-015의 대시보드 항목 각각에 대해 다음 네 가지를 한 줄씩 적는다.

1. **준비** — 어떤 데이터·서버 상태에서 시작하는가 (예: `data/008490_agents.json`이 없는 상태, 백엔드를 멈춘 상태, `news`가 빈 배열인 임시 픽스처를 놓은 상태).
2. **실행** — 실제로 치는 명령과 여는 경로 (예: `uvicorn app.main:app --reload` → `npm run dev` → `http://localhost:3000/dashboard` → 보유 종목 테이블에서 삼성전자 클릭).
3. **관찰 대상** — 화면의 어느 요소를 보는가.
4. **PASS 조건** — 무엇이 보이면 통과인가. 이진 판정이 되도록 쓴다.

AC-008 ④(원시 HTML 미해석)·AC-009(링크 4경우)·AC-010(네 상태)·AC-011(직전 응답 무효화)은 커밋된 데이터만으로 재현할 수 없다. 절차 문서는 이들에 대해 아래 **세 가지 준비 수단** 가운데 어느 것을 쓰는지 준비 단계에 지목하고, 검증 후 원상 복구 단계까지 적는다.

1. **임시 픽스처 파일을 `data/`에 잠시 놓기** — 실제 수집 데이터에 없는 값(`spec.md` §4 「안전한 링크」의 `javascript:` 케이스, AC-008 ④의 HTML 태그 문자열, AC-010 (d)의 빈 배열)을 만든다. 검증 후 임시 파일을 지운다. 커밋된 `data/*_agents.json`은 고치지 않는다.
2. **백엔드를 멈추거나 오류를 내게 하기** — AC-010 (c)의 오류 상태를 만든다.
3. **브라우저 개발자도구의 네트워크 스로틀링** — 아래 「지연 상태를 만드는 방법」. AC-010 (b)와 AC-011이 전제하는 **응답 지연** 상태는 이 수단으로만 만든다.

#### 지연 상태를 만드는 방법 (AC-010 (b) · AC-011 공통)

백엔드는 로컬 파일을 읽으므로 응답이 사실상 즉시이고, 라우트에 지연을 넣는 것은 코드 변경이라 PRESERVE 목록(`plan.md` §A.6)에 걸린다. 따라서 지연은 **브라우저 쪽에서** 만든다. 신규 의존성을 설치하지 않으며, 저장소의 어떤 파일도 바뀌지 않는다.

- **준비** — 개발자도구 네트워크 탭에서 스로틀링 목록에 **사용자 지정 프로파일**을 하나 추가한다. 이름 `news-delay`, 지연(latency) **5000ms**, 대역폭은 제한 없음(Chrome·Edge: Network 패널 → Throttling 드롭다운 → *Add…* / Firefox: 네트워크 → 스로틀링 목록의 사전 설정 가운데 지연이 충분히 큰 항목). 그 프로파일을 선택하면 **모든 요청이 똑같이** 5초 지연된다 — 종목별로 다른 지연을 줄 필요는 없다(AC-011의 판정 근거 참고).
- **되돌리기** — 검증이 끝나면 스로틀링을 `No throttling`으로 되돌린다. 되돌리지 않으면 이후 AC의 관찰 결과가 흔들린다.
- **절차 문서에 적을 것** — 위 프로파일 이름과 지연 값, 두 번의 클릭 사이에 기다리는 시간(약 3초), 관찰을 끝내는 시점(네트워크 탭에서 두 요청이 모두 완료), 그리고 `T5930`·`T0660` 두 제목을 어디서 얻는지(검증 전 API 1회 호출).
- **스로틀링을 쓸 수 없는 환경이면** — AC-010 (b)와 AC-011을 수행 불가로 기록하고, 그 사유와 환경을 `progress.md`에 적는다. "확인함"으로 적지 않는다(아래 품질 게이트).

## 엣지 케이스 (Edge Cases)

아래 항목 가운데 AC로 승격되지 않은 것은 구현 시 참고 사항이며 게이트가 아니다.

- **`008490` 파일 부재** — 허용 목록에는 있으나 `data/008490_agents.json`이 없다. API는 `404`(AC-004), 화면은 오류 상태(AC-010 (c))로 처리한다. REQ-001이 이 상태를 해소하지만, 해소 전에도 기능이 깨지지 않아야 한다.
- **허용 목록 밖인데 파일이 실재하는 `005380`** — `data/005380_agents.json`이 저장소에 이미 있다. 파일이 있다는 사실이 서빙 근거가 되어서는 안 된다. 허용 목록 검사가 파일 접근보다 먼저 오는 것으로 차단한다(AC-005).
- **필수 필드가 빠진 항목** — 문서 전체를 `500`으로 거부한다(AC-006 (e)·(f)). 해당 항목만 건너뛰지 않는다. 건너뛰면 화면에 표시되는 건수가 파일의 건수보다 적은데도 아무 신호가 없어, 데이터가 조용히 사라진다. 「유효한 뉴스 문서」가 단일 이진 술어인 것도 같은 이유다 — 부분 통과를 허용하면 술어가 항목별로 쪼개져 두 계층이 다르게 구현할 여지가 커진다.
- **모든 날짜가 파싱 불가** — 정렬 1·2단계에 해당하는 항목이 하나도 없으므로, 전체가 파일에 저장된 순서 그대로 나온다(§4 정렬 규칙 4). 오류가 아니다. 현재 허용 목록 4종목의 커밋된 파일에는 이 상태가 없다.
- **`news`가 빈 배열** — 「유효한 뉴스 문서」 위반이 아니다. API는 `200`에 빈 배열, 화면은 오류와 구분되는 "수집된 뉴스가 없습니다" 상태(AC-010 (d))다.
- **`url` 부재** — 정상이다. 허용 목록 4종목 가운데 `000660`만 `url`을 가진다. 제목을 링크 없는 텍스트로 렌더링한다(AC-009 ④).
- **`url`이 http/https가 아님** — 링크를 만들지 않고 텍스트로 렌더링한다(AC-009 ③). 백엔드는 값을 그대로 응답에 실어 보낸다(`spec.md` §4).
- **`url`이 대문자 스킴(`HTTP://`)** — 「안전한 링크」는 대소문자를 구분하지 않으므로 링크를 만든다(AC-009 ②).
- **파일에 `financials`가 있는데 응답에는 없어야 함** — 허용 목록 4종목의 파일 모두 `financials`를 가진다. 응답에서 제외한다(AC-003).
- **같은 날짜가 여러 건** — `005930_agents.json`에 실제로 있다. 파일에 저장된 상대 순서를 유지한다(AC-002 ④).
- **`005930` 파일에 `name` 키가 없음** — 응답에 싣지 않는 키이므로 부재가 문제되지 않는다(`spec.md` §4 「유효한 뉴스 문서」의 경계). 화면은 종목명을 대시보드의 기존 상태에서 가져온다.
- **뉴스 항목의 `summary`가 빈 문자열** — 「유효한 뉴스 문서」 위반이 아니다(값의 내용은 판정 대상이 아니다). 화면은 빈 요약을 그대로 표시한다. AC로 승격하지 않는다.

## 품질 게이트 기준 (Quality Gate Criteria)

- AC-001~AC-015 전체가 「검증 수단」 표에 지정된 방법으로 판정 가능해야 한다.
- 수동 판정 AC는 절차 문서의 PASS 조건을 인용해 `progress.md` 매트릭스에 기록한다. 절차 문서 인용 없이 "확인함"이라고만 적은 항목은 PASS로 보지 않는다.

- `backend/tests/test_news.py`는 CI 기능 단계 ⑤(`pytest backend/tests/ -v`)에 자동으로 포함된다. 본 SPEC은 `.github/workflows/ci.yml`을 수정하지 않으며, 수정이 필요해지면 그 사실 자체를 계획 이탈로 보고 `progress.md`에 기록한다.
- 신규 런타임 의존성이 없어야 한다 — `backend/requirements.txt`와 `frontend/package.json` 모두 변경되지 않는다.

### AC-001 예외 조항

`data/008490_agents.json` 수집이 실패한 경우에 한해, AC-001을 PASS가 아니라 `FAIL(차단됨)`으로 기록한 채 SPEC을 닫을 수 있다. 아래 **세 조건이 모두** 성립할 때에만 그렇다. 하나라도 빠지면 예외는 성립하지 않으며 SPEC을 닫지 않는다.

1. **수집을 실제로 시도했다.** 운영자가 `python scripts/orchestrate_stock_agents.py 008490 --save`를 1회 이상 실행했고, 실행한 명령과 그 실패 출력(오류 메시지 또는 종료 코드)을 `progress.md`에 그대로 적었다. 시도하지 않은 수집은 어떤 사유로도 이 조건을 만족하지 못한다 — "실행이 어려울 것 같다"는 판단만으로는 예외가 성립하지 않는다.
2. **파일이 없을 때의 동작이 그대로임을 증명했다.** AC-004(허용 목록에 있으나 파일이 없는 코드 → `404`)가 PASS이고, AC-010 안의 무데이터 상태 — `008490`을 선택했을 때 뉴스 영역이 (c) 오류 안내를 표시하고 헤더·포트폴리오 요약·보유 종목 테이블·주가 차트·GitHub 이슈 영역이 정상 렌더링되는 것 — 도 PASS로 기록되어 있다. 파일이 없어도 기능이 깨지지 않고 안내 상태로 내려앉을 뿐임이 확인되어야 한다.
3. **사유와 후속 조치를 남겼다.** `progress.md`에 (a) 수집 실패 사유, (b) 나중에 AC-001을 PASS로 바꾸기 위해 필요한 후속 조치, (c) `data/008490_agents.json`이 여전히 저장소에 없다는 사실을 함께 적었다.

세 조건의 증거는 `progress.md`의 「AC-001 예외 기록」 표에 적는다. 이 예외의 범위는 아래로 한정한다.

- **AC-001에만 적용된다.** AC-002~AC-015 가운데 어느 하나라도 FAIL이면 SPEC을 닫을 수 없고, 그 FAIL을 이 조항으로 면제받을 수 없다.
- **REQ-004의 `404` 동작을 완화하지 않는다.** 오히려 그 동작이 그대로임을(조건 2의 AC-004 PASS) 예외 성립의 요건으로 요구한다.
- **파일을 만들지 않아도 된다는 뜻이 아니다.** 수집이 가능해지면 다시 실행해 AC-001을 PASS로 갱신한다. `FAIL(차단됨)`은 종결 표시가 아니라 남은 일의 표시다.
